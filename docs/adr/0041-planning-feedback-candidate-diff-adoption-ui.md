# 单书规划反馈多轮候选、结构化差异对比与原子采用设计

日期：2026-11-08。状态：已接受。
依据：[F2](../plans/2026-11-07-creation-runtime-modernization/README.md) 第 6.1、6.2、6.3 节、FEEDBACK-002 特性定义，以及现行 [ADR-0026](0026-planning-feedback-candidates-and-adoption.md)、[ADR-0027](0027-planning-feedback-outline-ranges.md)、[ADR-0028](0028-desktop-planning-feedback-ipc.md)。

## 1. 目标与范围

本设计落实 FEEDBACK-002：
- 在单书规划（大纲/世界观/核心设定字段）阶段，提供基于作者反馈意见（feedback）的多轮候选生成、结构化差异（diff）确认与原子采用流程。
- 不影响正文审修闭环，不影响原有单次直接生成与全量重写。
- 纯单书前台界面与主进程契约推进，不依赖多书调度器与多书运行时。

## 2. 交互流程与安全不变量

```text
选定目标字段/底稿 -> 捕获底稿 (capture) -> 输入反馈与约束 (feedback/constraints)
 -> 生成独立候选 (begin & execute & stage) -> 结构化差异对比 (diffProse)
 -> 多轮迭代 (C1 -> C2) -> 明确确认原子采用 (adopt) 或 放弃关闭
```

1. **未确认不写库**：候选生成与暂存全过程处于隔离状态，主数据库正式字段不发生任何变更；只有作者在差异对比界面显式点击“采用”时，才调用 `client.adopt` 发起原子持久化。
2. **保护当前未保存编辑**：发起修订前检查目标字段是否存在未保存缓冲；若存在未保存编辑，提示作者提交保存或保留当前未保存版本作为底稿，绝不无声覆盖。
3. **结构化差异对比**：复用 `diffProse` 逐字比较当前正式底稿（`baseText`）与所选候选（`candidateText`），清晰呈现新增与删除，并统计变动处数。
4. **多轮候选追溯（F0 -> C1 -> C2）**：支持在上一轮候选（C1）基础上追加反馈意见产生下一轮候选（C2）；C2 的生成父本为 C1，但采用基线依然指向正式底稿 F0；候选历史完整可追溯。
5. **CAS 与原子采用**：采用时由主进程在事务内校验 `baseId` 与当前项目来源版本，执行单字段写入与收据归档；若底稿在期间被作者在其他地方修改，采用被安全拒绝，不产生脏数据。
6. **失败与取消安全**：生成中途取消或网络超时不落库任何正式数据，已生成的不完整内容丢弃或仅保留为失败记录，不产生脏状态。
