Status: accepted Stage 5B1 production generation slice after independent requirements, authority/receipt and physical/lifecycle review of current source identities, deterministic regressions and four isolated Electron scenes. ## Scope

Connect the existing main generation owners to one process-local scheduling broker per production controller composition. The broker is not another run owner or authorization channel. Only existing durable-owner generation is covered by this slice; legacy direct LLM IPC, embeddings, probes/discovery and direct domain writers remain explicitly unintegrated until their own implementation and evidence. No visible output, IPC request, schema, persistent authorization, dependency or DSH plugin change is authorized by this contract alone.

## Initial Admission Policy

F2 recommends starting cross-book pressure testing at concurrency two. This slice uses global/provider/credential/model limits of two and a project limit of one, preserving existing within-book sequential generation. A queue of 32 waiters bounds memory/backpressure, quarantine holds at most two parked physical transports, and a burst of one gives a runnable background head an opportunity after an interactive grant. These are finite host admission bounds, not permanent tuning, remote quotas or literary/performance qualification. Subject capacity is three times global plus queue plus quarantine bounds; stopped identities are not evicted to bypass a channel fence. Capacity exhaustion refuses new admission rather than clearing evidence.

The main controller supplies the captured runtime execution epoch as the private project grouping key. A manifest project ID, renderer field or view lease must not split or merge the native runtime's accounting. Trusted main-process test composition may inject the same admission interface with a lower finite policy for controlled serial/two-way comparisons; no renderer or public policy override is added.

Main-owned workflow/batch, import, Agent and finalization requests use the background lane; other existing author feedback/editor/planning requests use the interactive lane. Lane classification is derived from the admitted owner/operation, not a renderer priority flag. This policy does not preempt a dispatched request or promise that an already full global limit has an immediately free interactive slot.

## Queue And Final Admission

Existing same-nonce in-memory merging and durable receipt replay occur before queueing. Queueing must not reserve/mark an attempt, hold a database transaction, renew a lease, change a nonce, refreeze sources or reset the original root budget. Exact-root private cancellation removes undispatched waiters on pause/cancel/restart/close; it must not cancel another runtime.

After waiting, the owner repeats current runtime/epoch/maintenance, grant/revision, task/slot, immutable and source/model/lease checks, root state/cancellation and budget planning. The existing native reservation boundary repeats a trusted main-only final admission callback and atomically reserves/marks dispatch. A source or permission changed while queued must produce no physical attempt. Callback rejection is an admission conflict, not a storage failure. Existing protected-root, unknown, writer and receipt semantics remain authoritative.

The owner alone owns the dispatch-time short knowledge-source guard. After transport admission, a captured-runtime callback re-reads the exact original knowledge snapshot under the existing KB gate; it never retrieves or freezes a replacement. Current eligibility, planning and synchronous native reserve/mark/dispatch start occur inside that short guard, and the provider promise is awaited after it exits. Earlier execution-only controller/engine wrappers are removed to avoid inheriting a released reentrant gate token. Preparation, resume and formal-write guards remain. KB changes during the queue must reject with zero attempts; cancellation or revocation during the asynchronous read must still fail the final native callback.

## Physical Ownership And Identity

The private provider request may carry a permit only in memory; it must never enter a semantic replay task, event, receipt or portable artifact. Unused/rejected admission releases its permit; a dispatched permit belongs to the actual provider-finally boundary, not the service's logical cancellation race. A logical return can precede ordinary cooperative cleanup, so it must not immediately stop the credential. Hold the physical permit throughout an explicit five-second local-cleanup grace (the same scale as the existing runtime's bounded local close wait), with one bounded timer per unresolved physical flight. Actual finish clears that timer. Only work still physically unresolved after the grace parks/stops that channel without freeing counts or claims. This grace is not a new provider request deadline or permission to force release. Actual late settlement releases physical ownership idempotently, not unknown history or the channel stop fence.

Provider stream promises must cover their local reader-cancellation settlement and lock cleanup, including failed HTTP body cleanup. Logical onDone/onError notification must remain independent of local cleanup and cannot itself prove the physical promise ended. In particular, an already classified HTTP failure must not wait for body cancellation and become a root-budget timeout. The default main adapter joins a private logical outcome with a separately observed actual transport lifetime: the service may settle the original result while physical counts, permit and close tracking remain held. A late cleanup result cannot rewrite that receipt, start another request or reopen a stopped credential. Existing injected dispatch harnesses retain their original Promise contract; no public request or persisted task may supply physical-finish authority. Uncooperative local cleanup remains bounded/parked; neither a local promise nor reader cancellation proves a remote server stopped.

Private grouping derives the configured origin from each actual generation adapter's endpoint resolution. It does not mutate the frozen profile, wire URL, headers, raw model name, query/fragment or URL userinfo. In particular, Anthropic's existing removal of userinfo and Fetch rejection of preserved userinfo in other adapters are not changed to make a previously failing request send. Origin/key grouping is conservative; it does not prove a redirected destination's remote quota identity. No redirect policy is changed in this slice.

An adapter rejection or synchronous throw without a terminal callback retains its original value for the existing service failure classifier. Callback-free normal completion alone falls back to generic provider failure. Once the first terminal callback has decided the logical outcome, later rejection or cleanup cannot replace it. This preserves existing network/context classification without adding a new public error mapping.

## Verification And Rollback

Require current-byte deterministic owner/service/provider/broker and registered-controller regressions: shared limits, same nonce, queue-time source/model/lease/grant/root/close invalidation with zero new attempts, exact-root cancellation, ignored abort and delayed reader cleanup, quarantine/late finish, old unknown no resend and unchanged native receipt/rollback protections. Actual isolated two-runtime workflow scenes must supplement production composition checks. Serial/two-way throughput and all remaining network/domain routes are still full-feature gates.

No new persistent field means no new portable migration is introduced by this slice; existing run/budget/receipt histories and restore semantics remain. Rollback stops new scheduled work and drains/parks actual transports, retaining unknown and committed facts; lowering a trusted finite policy to one cannot erase or replay existing work.
