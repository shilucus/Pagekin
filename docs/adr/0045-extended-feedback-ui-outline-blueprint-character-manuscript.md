# ADR-0045: 规划反馈扩展呈现：大纲章范围、蓝图字段、角色Proposal与正文审修衔接 (UI-003)

- **状态**: Accepted
- **日期**: 2026-11-08
- **参与者**: 架构组、前端组、独立审查组
- **关联功能**: `UI-003`, `FEEDBACK-003`, `FEEDBACK-004`, `UI-002`
- **关联证据**: E14, E15, E16, E17, ADR-0021, ADR-0024, ADR-0041, ADR-0043, ADR-0044

---

## 背景与问题陈述

在 `UI-002` 中，我们实现了小说基本配置字段与大纲概览的试点反馈呈现、diff 预览与局部微调工作流；随后在 `FEEDBACK-003` 和 `FEEDBACK-004` 中分别建立了主进程与领域层的核心安全契约：
1. **大纲章范围（FEEDBACK-003）**：支持指定范围（如 3-5 章）大纲修订，严格保证范围外章节 100% 字节不被篡改；
2. **蓝图指定字段（FEEDBACK-003）**：单章蓝图局部字段修订（`mode: 'replace-range'`），消除全量覆盖整书蓝图的清空风险；严格执行角色身份闭包（Identity Closure）校验；
3. **角色 Proposal（FEEDBACK-004）**：角色反馈映射稳定 `characterId`，保留作者字段与定稿派生来源；章节蓝图存在时严格阻断整批角色重生；
4. **正文审修与定稿重开（FEEDBACK-004）**：必须绑定真实人审意见快照，就地合并更新同一草稿实体而不虚增不可变新版本草稿；定稿修改必须走 ADR-0024 重开流程，下游影响提示严格为只读警示，绝不自动级联修改后续章节。

然而，现有的用户界面（UI）仍局限于配置字段试点，尚未向作者直观呈现大纲章范围选择、蓝图字段细粒度对比、角色提议状态与正文审修重开警示。`UI-003` 的核心要求是：**将试点呈现扩展到大纲章范围、蓝图字段、角色 proposal 及正文既有审修衔接，且不扩大各 writer 的写入范围**。

---

## 决策核心

### 1. 范围外保护与独立可见证据（AC-1）
每个扩展对象与状态均具有独立的可见证据与视觉状态组件，不得从试点设计跨范围外推：
- **大纲章范围反馈组件 (`OutlineRangeFeedbackPanel`)**：
  - 提供章节范围选择（如从第 $M$ 章到第 $N$ 章）；
  - 呈现范围内各章节大纲条目的 Prose Diff 对比；
  - 显式展示只读保护徽章：“范围外章节（第 $1$ 至 $M-1$ 章，第 $N+1$ 章及以后）受保护且保持不变”。
- **蓝图字段反馈组件 (`BlueprintFieldFeedbackPanel`)**：
  - 呈现指定章节（第 $C$ 章）蓝图的候选字段（核心悬念 `suspenseHook`、用户指导 `userGuidance`、备注 `notes`、登场角色 `characters`）；
  - 允许作者按字段独立勾选采纳；
  - 显式展示单章隔离徽章：“仅修改第 $C$ 章蓝图，绝不影响全书其他章节蓝图”；
  - 校验失败（如包含未闭合角色引用）时，直接展示格式化错误并禁用采纳按钮。
- **角色 Proposal 反馈组件 (`CharacterProposalFeedbackPanel`)**：
  - 呈现角色提议差异卡片，明确标识角色稳定 `characterId`、映射动作（`map` 更新 vs `create` 新增）；
  - 强调作者字段（姓名、性格、外貌、背景）保留；
  - 当检测到已存在章节蓝图时，锁定“整批重新生成角色”按钮，并展示只读警示：“已存在章节蓝图依赖现有角色身份，禁止整批重生角色”。
- **正文审修衔接组件 (`ManuscriptReviewFeedbackPanel`)**：
  - 呈现真实人审意见与审修快照，提供逐块/段落合并预览；
  - 明确标注“就地更新当前草稿，不虚增不可变新草稿版本”；
  - 针对定稿章节，提供“需先重开为草稿”按钮，并呈现只读警示列表：“修改定稿不会自动更新后续已定稿章节，请作者自行注意剧情连续性”。

### 2. 合法部分采纳与非法结构零正式写库（AC-2）
- 作者最终确认的采纳范围（勾选的大纲范围或蓝图字段集合）在提交前必须经过结构合法性校验；
- 若输入或选择结构非法（如大纲范围为空、跨度倒置、蓝图字段类型错误、角色引用断裂），界面给出清晰红字/警告提示，**绝对禁止向主进程发起提交（零正式写入）**；
- 校验通过后，仅提交合法选择范围内的载荷，范围外数据与本地未提交的作者草稿缓冲（Buffer）100% 保持完好。

### 3. 双语、主题与设计一致性（AC-3）
- 界面组件复用纸墨（Paper & Ink）设计令牌（`var(--paper-*)`、`var(--ink-*)`、`var(--rule)` 等），完全融入当前书房与作品主工作台；
- 遵循 `useLocaleStore` 提供的中英文本地化契约，全部操作标签、状态提示与警示文案支持中英文双语无缝切换；
- 保持向后兼容：现有调用 `PlanningFeedbackDialog` 的组件无需更改即可继续工作，扩展视图通过 `ExtendedPlanningFeedbackDialog` 或 target 模式派发。

---

## 影响与风险评估

- **正向收益**:
  - 作者在界面上能清晰感知范围外内容得到保护，消除“AI 改一部分会把整本书冲掉”的顾虑；
  - 细粒度字段采纳赋予作者精确掌控力；
  - 角色稳定 ID 与蓝图保护机制在 UI 层落地，阻断冲垮下游剧情事实的误操作。
- **降级与回退**:
  - 若扩展呈现出现异常，可关闭扩展面板入口，作者仍可使用既有的大纲与正文手工编辑工作流；候选历史数据保存在 SQLite 中，不丢失。
