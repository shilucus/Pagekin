# ADR-0075: Main-Owned Foreground Reference Style

Date: 2026-11-13. Status: accepted for the bounded issued foreground reference style/done ownership contract,with current-source isolated execution and independent review in [Stage65 evidence](../plans/2026-11-07-creation-runtime-modernization/stage-65-evidence.md). This is not full import or background qualification.

Sources: [F2 sections4.4-4.5](../plans/2026-11-07-creation-runtime-modernization/README.md), [ADR-0074](0074-main-owned-foreground-knowledge-driver.md), existing `AnalyzeWritingStyleCommand`, `commitGeneratedNovelConfig`, ImportGeneration and ImportRunRepository receipt contracts.

## Bounded Ownership

The issued foreground reference workflow delegates the complete style/done step to the closed `import-generation:v1:style` request: existing run ID, execution owner/epoch and original selected model ID (or null when the existing root supplies it). Main owns sampling, frozen prompt/task construction, existing generation begin/ordinal0, style receipt prepare/commit/checkpoint, style-to-blueprints transition, same-owner heartbeat, failure/cancellation and actual physical drain. Renderer supplies no task, sample, source, root, nonce, model configuration, credential or replacement grant. Existing slot/root model and unknown/no-resend rules remain authoritative. No new schema, durable task ledger, allowance or background permission is created.

Main captures fallback finalized IDs and exact source bodies from the actual native database in the same synchronous transaction as begin. Sampling preserves first3/last2 imported chapters and the original finalized fallback: maximum chapter number down through maximum-minus4, skipping missing/empty bodies, trim then2000 characters. Frozen selected finalized/outbox identities and source guards remain necessary before dispatch and effect. Existing prepared receipts recover through their original source guard; committed receipts acknowledge their original saved value without revalidating later sources or generating again.

When an earlier import generation root exists, style begin explicitly binds that durable root. An exhausted physical-request or active-time budget must stop style, never trigger implicit creation of a new root or allowance. A completed import clears its executor as part of the existing complete transaction. Reading its committed style receipt is consequently a pure historical replay: the result carries `execution: null` only with `replayed: true` and the actual completed run. It does not renew, reconstruct or echo a writing lease. Active runs retain exact owner/epoch and positive-expiry validation, and renderer never treats the historical receipt value as the current saved config. If the effect/checkpoint committed but the style-to-blueprints transition was interrupted, recovery completes only that missing transition under the existing lease, without repeating the model request, source validation or effect. Once the run has passed style, its committed-style replay is read-only and does not renew or advance it.

The process-local database/run stage flight fences competing legacy DB writers and generation begin/execute/pause/resume/restart/discard mutations targeting that run. Explicit request-cancel remains reachable; the driver observes it and owns cancellation/drain. Whole-step runtime work and controller handler lifetime remain held until timers, generation operations and local physical requests have settled. Sender destruction and project close unblock foreground handshakes. A stale owner/epoch cannot fail or cancel its successor. A genuine provider/storage/source failure retains precedence over a later stop.

## Preserve Author Draft CAS

Main cannot read unsaved renderer buffers. Replacing the original precommit CAS with an unconditional main commit is not equivalent and is not accepted here. Two automatic foreground handshakes retain the existing contract, without new author-facing controls or approval authority:

1. Before physical dispatch, main emits an identity-bound opened event with its handle/model and opaque one-use token. Renderer binds the existing verified full-snapshot runtime and reasoning subscription, freezes expected config at the original pre-dispatch point and acknowledges readiness. No request is dispatched before readiness.
2. Before a new effect is prepared, main emits commit-ready with the main-owned style, exact handle and another opaque token. Renderer calls the unchanged `commitGeneratedNovelConfig`; its persist callback acknowledges the token only after the existing entire-config CAS succeeds. Main performs prepare/commit itself. The ACK promise returns the actual saved style only after the durable effect succeeds; it does not wait for renderer store completion. A rejected precommit CAS prevents the effect. Concurrent edits during persistence retain the existing saved ledger, dirty author values and `GENERATION_SAVED_WITH_NEWER_AUTHOR_DRAFT` result.

ACK requests carry only identity/token/phase and a closed accept or existing failure decision, never replacement content or error text. Duplicate in-flight ACKs join the same result. A completed token may acknowledge its original result within its existing live foreground operation; an unknown process-local token cannot reconstruct permission. After a lost response or restart, the durable style entry reconciles the original committed receipt without a new model request or commit-ready decision. Projection failure after a formal commit cannot rewrite the import as failed or invalidate the receipt. Renderer waits for both the main step and its store handshake to settle before reporting the step result.

## Existing Visible Projections

No layout, copy, control, asset or stage is added. `AnalyzeWritingStyleCommand` supplies exact existing bilingual logs: imported sample count, fallback sampling, no finalized chapters, sampled count, read failure, empty samples, AI invocation, empty result and saved style. BaseWorkflowCommand supplies10/90 progress and prompt-budget projection; the orchestrator supplies100. Existing `workflow-main-generation` supplies verified full snapshots, replace or per-artifact deduplicated append, diagnostics/activity, same-session reasoning and cleanup. The versioned event carries exact project/lease/import execution identity and monotonic sequence; projections are not input to formal persistence.

Author-manuscript/fill-empty, unissued legacy consumers and global/blueprints/refresh retain their existing contracts. `novel_import` remains background-unqualified. Static source checks, fake native execution, Electron interactions, real-model quality and platform qualification are separate evidence layers.

## Acceptance And Rollback

Acceptance requires registered IPC with isolated fictional SQLite, exact sampling/task/model/ordinal and original receipt/transition, prepared/committed replay and unknown no-resend, sender/session/source/lease fencing, competing writers, CAS before/during commit, snapshot/reasoning readiness, cancellation/close/drain and production renderer delegation. Independent review, focused regression and fresh applicable quality/build precede commit. Rollback drains the operation and preserves all receipts/checkpoints/dispatch history; it may restore only the previous issued foreground style path, never clear history or retry unknown work.
