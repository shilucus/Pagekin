## Original Order And Foreground Projection

Only an issued reference delegates its complete refresh step to the main-process reference authority. Author-manuscript and unissued paths retain their current implementation. Reuse the existing private sender issuance,project/canonical DB/resources,original execution owner/epoch and source/grant guards;do not issue another grant,lease,root or allowance. The process-local refresh flight fences same-run legacy writers while ordinary reads and request-cancel remain reachable. Main owns heartbeat,checkpoint,terminal handling and completion;renderer is only the current-view projection adapter.

Preserve exact original order:if refresh/done is missing,perform refresh under heartbeat,renew,then complete that checkpoint;project100;check cancellation;renew;check cancellation;complete the run;only then complete the original reference grant. Existing refresh/done skips projection and checkpoint rewrite. The original projection logs "Refreshing project data..." in the existing locale,uses the existing file-tree five-second best-effort helper,then sequentially awaits character and draft loading. Preserve actual existing store error behavior and any rejection;do not turn all loads into best-effort. The file-tree timeout does not prove its underlying request ended;its existing per-request resource/session guards remain responsible for outstanding work.

Closed reference-knowledge:v1:refresh and refresh-ack carry the original reference/execution and an unpredictable per-flight projection token. Events are bound to original project lease,sender,reference,execution and sequence. ACK means only that the existing projection Promise settled,not author approval or trusted evidence of a domain write. Extra fields,foreign/stale sessions,senders,tokens or executions reject. A failed projection ACK carries no arbitrary renderer message;it uses the existing localized import-check failure template with the finite IMPORT_RUN_REFRESH_PROJECTION_FAILED diagnostic. Renderer retains its local original projection exception when reporting that same failure. No new layout,control,asset or workflow-visible state is introduced.

## Completion And Recovery

The refresh flight retains its work claim and same-run writer fence through checkpoint,run completion,original grant completion and outstanding main-owned work. No release-and-await gap and no renderer-controlled bypass flag is permitted. The authority may factor its existing grant completion into a private helper available only after matching the original issuance;public complete keeps all original issuance/writer checks. No competing knowledge/chapter work may be admitted during refresh.

ImportRunRepository.complete remains the sole run writer and clears owner/lease while advancing epoch. After that commit,never renew,resume,fail or cancel the completed run. Grant failure preserves that completed run and the still-valid original issuance. Reentry with that same private issuance may only retry its original grant completion,without another refresh/checkpoint/run completion. Revoked,destroyed,lost or unrelated issuances never reconstruct write authority. If both run and matching original grant are already completed,history is read-only and returns execution:null without a lease or new grant;the original project/run/revision/manifest binding must still match. An active/pending grant requires the original valid issuance. Renderer refresh delegation must precede the old completed-run early return so a valid pending original grant is not skipped.

Keep current cancellation boundaries and actual error priority. A real projection/storage/source/lease failure cannot be covered by a later cancel;stale execution cannot mutate a successor. Cancel while a live projection awaits settles at its original safe boundary;destroy/close cannot trust an impossible future renderer ACK and must stop the foreground wait while existing main resource claims drain. Late projection/ACK/cancel cannot rewrite completed facts. Grant cleanup failure is not a failed import commit.
