# 规划反馈先保存候选，按原底稿原子采用

日期：2026-11-07。状态：已接受，仅限本包八个内部文本目标；本轮聚焦回归与独立复审证据见 [Stage 2A](../plans/2026-11-07-creation-runtime-modernization/stage-2a-evidence.md)。依据为 [F2](../plans/2026-11-07-creation-runtime-modernization/README.md) 第 6.1、6.2、7.8 节，以及本轮用户对 35 项功能、版本化接口和迁移的实施授权。

## 范围

本包是 FEEDBACK-001 的内部内核切片，不代表整个功能完成。首批目标是 `coreOutline`、`worldSetting`、`goldenFinger`、`protagonistProfile`、`globalGuidance`、`writingStyle`，以及架构 `premise`、`worldbuilding`。大纲章范围、蓝图字段、角色 proposal、正文审修分别沿后续适配交付；不引入能任意写表的通用 revision 框架。

本包不增加可见文案、布局或交互，不开放新的 renderer IPC、公共 API 或自动生成入口。缺少设计证据的可见部分继续受 F2 第 6.3 节限制。候选内核不读取真实配置或作品作为开发夹具，不执行写作 Skill 脚本。

## 两种来源

- `adoptionBase` 冻结项目、目标、正式值、相关作者来源快照及单调修订号；它是最终采用的 CAS 基线。
- `generationParent` 是本轮真正输入的正式基线或不可变父候选及其正文 hash。`F0 -> C1 -> C2` 尚未采用时，C2 使用 C1 生成，但仍对 F0 采用。父候选必须同项目、同目标、同基线；不允许跨书或跨目标借用。
- 反馈、不可改约束、范围、run、attempt、artifact、模型和 Skill 来源随候选冻结。候选创建不更新正式作者事实；改变反馈或底稿需显式新操作，不能改旧记录或静默 rebase。

底稿和父候选不是 renderer 声明的身份。主进程读取冻结来源并构造实际 generation task，将 context/task 和现有来源指纹持久绑定。候选入库前，服务从真实 generation repository 读取当前项目的 attempt、artifact 和完成收据，核对实际请求与冻结任务一致。仅持久化 `stop` 且完整落盘、无失败或未保存尾部的结果可成为可采用候选。无用量或不可信用量的完整结果可以保留账本 `unknown` 并保存候选，但不能据此改账或重发；没有完成收据的投递未知、取消、截断、失效来源和只带 renderer hash 的结果不能获得采用权。

## 采用边界

1. 采用请求明确指定候选、幂等键、全量/部分/手改决定及最终完整字段值。主进程按目标既有合同校验最终载荷，不把生成格式约束无依据套到作者自由编辑上，也不自动补未选择的字段。
2. 一个数据库事务中重验项目、来源修订、原值、候选与范围，调用现有 `ProjectCoreRepository.update` 单字段 writer，写入采用前快照和采用收据，并消费旧基线。候选、正式作者字段、历史和收据不能部分成功。
3. `idempotencyKey` 是本包唯一的操作标识，不另存重复 `operationId`。幂等绑定候选版本、实际最终载荷 hash、目标范围及固定 `decisionSource: 'author-action'`。来源由专用主进程采用入口固定，不接收调用方自报的人审/机器批准；未来 automation 需独立扩展可信授权合同。已提交同键同载荷先返回原收据，不重复 writer；同键异载荷拒绝，不因后来底稿变化把重放变成新提交。
4. 全量、部分或与原值相同的采用都会推进共享来源修订号并关闭旧基线。在同一旧来源状态独立捕获的其他 base 也因此失效，不只关闭本次 `baseId`。依赖旧基线的其余候选和后继只读冲突，不将剩余内容自动搬到新基线；作者明确选择新底稿后才能开始新 lineage。重放原收据不再推进修订号。
5. 普通编辑、导入和其他实际作者写入口均能使旧来源失效。不能只在新采用路径递增 revision；同事务回滚同时回滚 revision，`A -> B -> A` 仍可识别为已变化。纯时间戳、角色动态缓存、剧情树缓存不是作者来源变化。

本包不触碰定稿、重开、删除、唯一领域 writer、outbox 或后续连续性水位。采用不自动改写后续章、角色派生或任何范围外事实。

## 持久化与恢复

- M08 只经 [desktop registry](../../electron/migrations/desktop-registry.ts) 注册、识别 schema 和执行事务；版本数字只由安装 lane 管理。旧数据原样保留，不以清理候选、WAL/SHM 或降级 schema 处理失败。
- 本包表分别保存作者来源修订、不可变基线、不可变候选和采用历史，不复用正文 `revisions`。记录读取和效果提交使用明确捕获的 DB/项目身份，不在内部临时切换全局 current project。
- 原项目重启可读回历史和已提交收据，但不因此重发 unknown 模型请求。新副本恢复与原项目重启不是同一种授权。
- 本包每个字段加入现有便携字段策略。作者/候选正文和必要历史保留；混合 JSON 使用闭集解析和逐字段投影，机器身份、凭据、旧 nonce、旧执行能力及其混合摘要不转移。允许内容的投影 hash 必须重新计算，不能继续带入被排除内容的摘要。
- 便携读取兼容旧包并在隔离恢复中迁移。恢复副本中的旧候选与采用收据可读但不可重放；明确选择当前底稿并开始新 lineage 时，只能复制其允许正文和可追溯来源，重新核验当前来源/范围并取得新的采用能力，不修改旧历史。
- 本包的迁移与便携验收在本包完成，不依赖未来 runtime、API 或 automation 状态。任何未分类的新字段使导出/导入失败关闭。

## 验收与回退

必须覆盖父链与原基线 CAS、最终手改/部分采用、目标外字节不变、同键重试和异载荷、同内容采用、ABA、事务中断回滚、重启、7/8 旧包恢复、新副本冻结/新 lineage 及二次导出。测试只使用可恢复的虚构内存或隔离项目。主进程真实来源证明与便携混合 JSON 的拒绝分支须独立审查。

停用新入口可阻止新候选/采用，但不删除历史或回写旧事实；schema 不自动降级。此 ADR 不接受未来多 runtime、执行 grant、公共 API 或人工终验合同，也不证明模型文学质量、可见设计或平台资格通过。
