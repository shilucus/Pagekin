# ADR-0051: 创作 CLI 驱动、run --wait、收据打印与非交互人审消费契约

## 状态
已接受 (Accepted)

## 上下文
随着 `API-001`（本机领域 API 与安全入站通道）的落地，系统具备了受控的白名单命令、Bearer Token 身份认证、双重幂等绑定与序号事件续读能力。
为了支持批处理创作、自动化脚本与外部 CI 工具驱动创作过程（`CLI-001`），需要提供一个轻量、标准且安全的外部命令行客户端（CLI）。
然而，CLI 必须遵循以下严格设计约束：
1. **不重复造轮子**：CLI 纯粹作为客户端调用主进程入站 API，严禁在 CLI 侧自建写库、直接连接 SQLite 或复制工作流引擎实现；
2. **受理不等于完成**：创作任务是耗时业务；`submit` 仅表示任务被服务端成功登记，绝对不能当成创作完成；`run --wait` 必须通过轮询序号事件流与最终收据来确认真实终态；
3. **明确的退出码与结构化输出**：CLI 的进程退出码与 JSON 输出必须清晰区分：真实完成（0）、业务失败（1）、任务取消（2）、未知终态（3，禁止自动重试）、待人工审核（4）、鉴权与权限越界（5）；
4. **秘密不入命令行与日志**：Token 与凭据支持环境变量（`PAGEKIN_API_TOKEN`）或标准输入注入，日志与标准输出中对 Token 自动脱敏，杜绝从 `ps`/`argv` 泄露秘密；
5. **严禁自动化自批**：`approve` 命令必须验证调用方是否具有 `human_review` Scope；严禁使用普通 task 凭据自动批准人审，保证人工把关防线不可穿透。

## 决策

1. **CLI 架构与入口 (`scripts/cli/creation-cli.ts`)**:
   - 提供基于 TypeScript / Node 的标准客户端实现；
   - 暴露 5 组核心子命令：
     - `submit`: 异步提交创作任务，打印初始 Receipt 与 taskId 后立即退出；
     - `run --wait`: 提交创作任务并持续拉取增量事件流（`workflow:events`），直至到达终端状态或超时，输出最终 Receipt 并以标准退出码退出；
     - `events`: 监听或续读已有任务的序号事件（支持 `--after <seq>` 和 `--wait`）；
     - `receipt`: 依据 `idempotencyKey` 或 `taskId` 查询持久化领域收据（回包丢失对账）；
     - `approve`: 提审或审批人审待办项，严格验证 `human_review` 权限。

2. **退出码与状态映射 (Exit Code Contract)**:
   - `0`: 成功完成 (`succeeded`)；
   - `1`: 执行失败 (`failed`)；
   - `2`: 已取消 (`cancelled`)；
   - `3`: 未知终态 (`unknown`，存在不一致风险，禁止无脑重试)；
   - `4`: 等待人工审阅 (`pending_review`，需要交互介入)；
   - `5`: 鉴权失败或权限不足 (`UNAUTHORIZED` / `HUMAN_REVIEW_SCOPE_REQUIRED`)。

3. **断线重连与幂等安全**:
   - `run --wait` 在遭遇网络断连时，利用原 `idempotencyKey` 重试状态与收据查询，绝不重新发送带不同参数的新任务；
   - 遇到 `unknown` 终态时立即终止等待并退出码为 3，打印诊断指引。

4. **人审 Scope 门禁与物理通道限制**:
   - CLI 执行 `approve` 时必须显式持有 `human_review` Scope；若仅提供 `task` 凭据，直接报错退出（退出码 5）；
   - 若主进程报告物理人审渠道锁定（HTTP 423 / `HUMAN_REVIEW_SCOPE_REQUIRED`），明确提示等待桌面端开启。

## 效果与保证
- 实现与桌面 UI 完全对称的命令行驱动能力；
- 杜绝 CLI 侧越权写库与非法自审；
- 为后续 `AUTO-001`（自动化创作流水线）和 `MCP-001`（MCP 工具对接）提供可复用的高可靠客户端底座。
