## Durable Commit And Synchronization

Prepare `blueprints:<checkpoint>` / `chapter-blueprint-range` using the original `import-blueprints-${runId}-${start}-${end}` replace-range request and actual generation handle. Keep existing source guards and atomic canonical blueprint/effect/checkpoint transaction. Prepared recovery uses the original payload and source guard without new model calls. Committed history is canonical readback,not a new fact commit or current-fact overwrite.

Immediately after a durable range commit,`range-committed` projects its canonical receipt into the existing workflow context. Main then reads the durable `characterSyncOperation`;completed operations are read-only,otherwise main calls the existing directory proposal service and completes that same operation through `BlueprintRepository`. Pending proposals remain pending approval;no character create/merge/adoption is authorized. `range-synced` projects the canonical completion receipt and existing fileTree/blueprints refresh only after successful synchronization. Original completion logs remain unchanged.

Those two context/refresh events and command completion logs apply only to newly inferred ranges. Existing checkpoint/prepared/committed replay follows the original replay helper:retry the saved synchronization operation and project visited progress,without repeating command logs,refresh or context assignments. `postCommitSyncBatchId` likewise reconstructs the old command-specific error only for a newly inferred committed range,not a different replay-helper error.

Postcommit synchronization failure preserves the committed range and exact retry operation/message,marks only the still-owned blueprints run failed,and returns closed optional `postCommitSyncBatchId` paired only with the generic failure code. Renderer reconstructs the existing `ImportBlueprintPostCommitSyncError` from canonical storage rather than renderer-provided payload. Reentry synchronizes that operation without regenerating the range. A crash after all commits but before advance only supplements synchronization/transition. Completed/completed history returns execution:null and performs no synchronization write or lease reconstruction;active later-stage history is read-only. No durable fact is rolled back because of a projection failure.
