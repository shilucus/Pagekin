# ADR-0072: Import Query Materials And Shared Generation Budget

Date: 2026-11-13. Status: accepted for the bounded Stage62 implementation, subject to its independent source and runtime acceptance.

Sources: [F2 sections5.1/5.2/7.5](../plans/2026-11-07-creation-runtime-modernization/README.md), [ADR-0023](0023-provider-owns-context-capacity-no-token-preflight.md), [ADR-0064](0064-bounded-concurrency-for-single-book-network-tasks.md), [ADR-0071](0071-foreground-reference-embedding-root-budget.md), and the actual reference-global consumer in `import-novel.command.ts`. The user's all35 implementation authorization includes this contract and isolated persistence/migration verification. It does not authorize real models, projects or credentials.

## Scope And Materials

The actual foreground reference-global command uses a versioned, project-session-scoped main-owner entry with only its generation handle and current import execution authority. Main derives the frozen context and the four topics from `getImportInferenceTopics`: worldview, protagonist, conflict, style, in that order, each topK5, with the project's writing language. It does not accept renderer queries, topic plans, embedding profiles or budgets. The author-manuscript branch keeps its reference-excluding writing-context search; ordinary KB search is unchanged.

Stage62 remains serial. Bounded overlap and comparative performance are a later, separately accepted increment. Results retain the original hit order, scores, file names, text, formatting, empty-result versus unavailable distinction, and full prompt material. Existing per-topic log wording/order and progress values remain; the managed branch emits those logs from the returned ordered receipts. No new visible layout, control, copy or resource is introduced. This timing/ownership change is grounded in F2's main-owned material preparation and per-topic error contract, not a new visual design.

Ordinary known HTTP or invalid embedding responses keep the existing FTS fallback. A topic whose actual search reports unavailable records that explicit result and does not prevent other topics. Authorization, cancellation, source-integrity, budget, storage and transport-unknown failures are hard barriers, not unavailable material. They must pass through the embedding and renderer catch boundaries and stop new generation.

The eight new `GENERATION_IMPORT_QUERY_*` barriers use only the existing bilingual `error.unknown` template with the original diagnostic code. This is the sole error-display difference, grounded in the existing generic catalog and the hard-barrier requirement above. It makes no claim about saved results, the cause of uncertainty, or permission to retry. Existing action-oriented import/generation explanations do not accurately cover these states and are not reused. Detailed new recovery copy remains outside this stage's design evidence; the generic wrapper is not acceptance of such copy.

## Durable Identity And Recovery

A plan is anchored to the immutable reference `import_runs.root_run_id`, not the current descendant, UI nonce, model, owner or epoch. It freezes the first actual generation root and global slot/input/configuration binding. A descendant or retry cannot allocate a second plan or move unresolved work to a fresh root. A mismatched root or frozen input fails closed. This does not borrow the document-embedding root or allocate four additional requests.

`import_query_plans` has the closed columns `import_root_run_id`, `generation_run_id`, `root_action_id`, `manifest_fingerprint`, `binding_json`, `binding_fingerprint`, `state`, `created_at_ms`. Its state is ready or recovery_unknown. `import_query_topics` has `query_id`, `import_root_run_id`, `topic_key`, `state`, `marked_at_ms`, `outcome_json`, `settled_at_ms`, `physical_closed_at_ms`, `receipt_json`, `receipt_fingerprint`. The deterministic root/topic identity is unique; the closed state set is prepared, dispatch_marked, completed, unknown. Plan plus all four topics are created atomically. A partial existing plan is corrupt, not permission to fill missing history. No generation attempt or ordinal is fabricated.

Configuration is captured once for pending material work. Operational binding fields may retain a private comparison fingerprint, but never a plaintext API key or endpoint. They are excluded machine authority in portable history. Remaining prepared work must match the frozen source; it cannot silently choose the current profile or replenish limits. Completed material replay does not need a new provider configuration or physical request.

Each completed topic has an immutable available/unavailable receipt and integrity fingerprint. Available receipts contain durable original-source evidence without `projectStorageRoot` or `runtimeEpoch`. A dedicated durable verifier checks current resources and fresh authority, then the original IDs, versions, hashes and exact material; it neither searches again nor embeds again. A new epoch does not recreate the old capability. A marked request without a complete provable receipt is not retried: preserve its consumption and fence the plan/root as recovery_unknown. Missing/corrupt receipts or changed original sources do not become empty results. Explicit ordinal generation replay remains the original request/receipt and does not create new work.

## Shared Budget And Physical Lifetime

Actual query fetches consume the existing generation root policy. Prepared/FTS-only/smoke work consumes zero physical requests; atomic final admission and dispatch marking consume one permanently. Generation reservation occupancy plus marked query requests share the original maxPhysicalRequests. There is no new floor, multiplier, retry allowance, time allocation or token hard cap.

The same root activity clock measures the union of actual query and generation physical intervals. Queue waiting and pure retrieval do not start physical activity. Native-private holds distinguish logical settlement/cancellation from physical closure; pause/cancel must not clear a live interval. The owner starts a generation hold at the actual dispatch boundary and releases it from actual provider physical completion, not a cancellation race. Query observer marks immediately before fetch and records known/unknown outcomes; final physical release is separate. Existing global scheduler limits, credential grouping, quarantine and close/drain protections also apply to query transports.

Live holds are native database/root capabilities, shared by repository instances, not reconstructed from caller data. Lost open intervals, clock rollback, unsafe elapsed arithmetic or persistence failures fence further dispatch and effects without refunding or guessing downtime. Factual settlement/physical cleanup of already-issued work remains allowed. Final dispatch and material completion recheck the frozen import source, execution authority, cancellation, current resources and applicable budget. No native transaction spans an await.

## Migration And Portable History

Register M18 centrally for schema18 to19 with both standard/donor fingerprints. Existing schema18 projects acquire empty query tables; migration does not fabricate physical history or unfreeze existing roots. Older migration comparison domains explicitly exclude the new tables until their applicable version.

Safe root/run/topic relationships, state, physical outcome and timestamps are nonreplayable history. Manifest/configuration bindings and private receipt fingerprints are excluded X fields and neutralized to NULL in a frozen copy. Mixed receipt JSON is R, with an explicit closed whitelist projector for readable material and source evidence; exclude paths, runtime epochs, endpoint/configuration/credential identities and registry hashes derived from them, including their original digests. Projection hashes bind only the projected object. No raw mixed JSON is copied as H.

Export/restore validates both directions among an existing plan, four topics, generation run/root and frozen history. It rejects a missing row named by the sidecar, missing topics of a present plan, missing/mismatched H parents, or missing freeze coverage. Export excludes generation binding JSON; checks do not pretend to recover lineage from that removed authority. Source18 packages necessarily have no query history; this is not permission to invent it. There is no source signature: coordinated deletion of an entire plan group and its sidecar plus rewritten package metadata cannot be distinguished from never having had a plan by the remaining parent fields. No extra parent-table marker is introduced or complete-archive authenticity claimed. Two-generation restore keeps copied history nonexecutable, while unrelated newly created local roots remain usable. History readability is not an execution grant.

## Acceptance Boundary

Required evidence: actual registered IPC and actual reference consumer; bilingual full-material parity and preserved author routing/error semantics; same-root generation/query last-credit competition and physical activity union; queue/cancel/drain, source/grant changes and persistence failures; completed replay after reopen with zero new fetch; unknown/fresh nonce/import restart rejection; M18 rollback, old-schema transition and two-generation portable history including forgery rejection and usable new local work. Independent review must inspect the integrated current source and raw results. This contract does not itself complete SCHED-001/002, either full import migration, model quality, headless or target-platform qualification.
