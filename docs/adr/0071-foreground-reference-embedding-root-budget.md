# ADR-0071: Foreground Reference Embedding Root Budget

Date: 2026-11-13. Status: accepted for the Stage60 foreground knowledge increment after independent contract review.

Sources: [F2 sections5.2/7.5](../plans/2026-11-07-creation-runtime-modernization/README.md), [ADR-0069](0069-reference-embedding-dispatch-barrier.md), [ADR-0070](0070-foreground-reference-knowledge-issuance.md), the actual reference import restart lineage, and the existing generation activity allocation in `main-generation-plan.ts`. This decision introduces an embedding policy; previous generation limits and lease TTL did not already supply one. The user's all35 implementation authorization includes this ADR and its migration, not real-model or real-project operations.

## Identity And Allocation

The budget belongs to the project's immutable reference `root_run_id` lineage, not a grant, operation, sender, execution owner, descendant `runId`, model or parallel worker. The existing reference restart creates another run but retains `root_run_id`; it cannot allocate another budget. Freeze the first complete, non-placeholder manifest and reject a descendant with a different manifest. An independently authorized, unrelated root has its own budget; reuse of another root's complete and verified KB document makes no physical request and does not charge that other root's historical requests to the new root. Any prior physical dispatch still blocks an incomplete document across all roots and grants.

At the first managed foreground prepare, including FTS-only preparation, calculate the potential physical plan from every immutable chapter snapshot: `R = sum(ceil(chunkText(content, initialChunkSize, initialOverlap).length / initialBatchSize))`. Use the actual corrected chunker and normalized explicit batch size used by this consumer for both protocols. Require a complete, positive safe-integer plan; no32 floor, retry allowance, concurrency multiplier, partial manifest or fabricated one-request minimum. Read and release each chapter's chunks in turn; do not retain full-book chunks. Synchronous calculation precedes the short final issuance transaction, which rechecks the complete manifest, snapshot integrity, runtime and execution authority. No native transaction spans an await.

Freeze initial chunk size, overlap, batch size, policy version, manifest and `R`. A new explicit launch may still choose current embedding inputs as ADR-0070 permits, but it inherits the original limits and consumption. Smaller batches or different chunking may exhaust that allowance or conflict with existing chunk-set receipts; do not replan, increase the allowance, silently change options or fall back to FTS to hide a budget failure. FTS-only and release-smoke requests consume zero physical requests.

The full input manifest is not the new-chapter execution subset. Both direct preparation and worker finalization bind every input chapter in the original transaction through `reference_import_manifest_chapters(import_run_id, chapter_number, snapshot_run_id, snapshot_chapter_number, source_id, source_chapter_number)`. New chapters reference their own snapshot; duplicates reference a specific completed, same-purpose snapshot whose stable mapping, source affiliation, title, hash and size exactly match the input. The logical global chapter number is independent of the snapshot primary key: legacy normalization can assign a new global number without rewriting the old snapshot's number. Body hash and size remain verified. No duplicate body is stored. The binding retains the input's logical source identity because existing legacy adoption can update those two fields on old chapter rows; later manifest reconstruction uses the binding identity and snapshot body/metadata, not a newly inferred alias or historical duplicate set. Restart copies these bindings while preserving their snapshot targets, including incomplete same-root snapshots; cross-root duplicate snapshots remain completed-only. Foreign keys prevent deleting snapshots still referenced by another run; deleting an otherwise removable owner only cascades its own bindings.

New policy `reference-embedding-budget-v1` assigns `T = R * 112500` milliseconds. The unit is explicitly borrowed from the existing generation operational allocation `3600000 / 32`, not measured embedding latency, a provider timeout or an SLA. This is its first accepted application to embedding. Reject unsafe arithmetic before publishing authority. No token estimate or token-liability rejection is introduced. Later global/style/blueprint generation retains its existing separate generation budget; this decision does not combine or replace that ledger.

## Dispatch, Activity And Effects

Every real batch uses the existing synchronous admission transaction: recheck current resources, grant, source, execution, cancellation and budget, then atomically reserve one request and persist its dispatch mark immediately before fetch. A transaction failure performs neither send nor debit. A persisted mark consumes one request permanently, regardless of HTTP failure, invalid vectors, cancellation or transport unknown. Settlement records the original mark's factual outcome and cannot mint another request or new effect authority.

Activity is the union of root intervals with actual dispatched fetch/response-body/settlement work, not a sum of parallel request durations. Queueing before dispatch, chunk calculation and KB work after all physical requests drain do not count as active. Start an interval on the first mark and close it after the last physical request and settlement has drained, across every descendant and flight. Cancellation only blocks new work; it neither stops the clock nor releases a physical slot early. Pausing and new authorization preserve accumulated time. This increment adds no request timeout or forced abort; a request can outlive the allowance locally, but late work cannot authorize a new effect. It is not a bounded transport-lifetime qualification.

Before dispatch require `spent < R` and active time below `T`. At KB write, document receipt and final run-receipt boundaries require `spent <= R`, so the last legitimate request can commit, together with the same current activity, source and authorization checks. Never hold a native transaction over vector-storage awaits. Preserve complete vectors, the previously allowed whole-document FTS outcome, original-batch failure ordering and hard integrity barriers. A previously committed KB document remains a fact when a later separate run receipt is refused; do not describe that as a successful run receipt.

Closed intervals survive a new explicit launch or process restart with their accumulated value. An open persisted interval without its original native-process flight is `recovery_unknown`: preserve marks and recorded consumption, refuse new dispatch/effects and never infer that a remote request stopped or refund it. A clock rollback during an open interval and unsafe elapsed-time arithmetic fail closed; do not subtract elapsed time or invent a precise duration. Factual settlement may still be recorded while the budget is fenced. Any budget persistence failure poisons that native database/root for further dispatch/effects, even if a durable fence cannot be written; already-issued settlement remains allowed to converge. Native-private capabilities and poison are shared across repository instances, not reconstructed from caller assertions or portable history.

## Migration And Portable History

M17 is registered only in the central desktop registry. Its twelve-field `reference_embedding_budgets` row is keyed by `root_run_id`. During migration, any existing reference descendant with an execution epoch above0, a stage other than parsing/prepared, any grant in any state, any dispatch or any run KB receipt marks the whole lineage `legacy_unbudgeted`. Its manifest, plan, limits and consumption/time fields are NULL, meaning unknown, not zero. It cannot receive a new grant, physical dispatch, KB effect or run receipt. Existing history and ordinary read-only inspection remain; do not invoke the mutating import fast path and call it read-only. Old parsing/prepared lineages with epoch0 and none of those histories have never passed the existing knowledge/execution guards and may freeze their first plan only when their complete input can still be proven. M17 backfills bindings only to each old run's own valid snapshot rows; incomplete duplicate subsets or changed legacy identities fail the existing complete count/size/hash checks, rather than guessing their missing inputs. A new descendant cannot evade a legacy marker. Newly constructed post-M17 `knowledge/ready/epoch0` rows with no lineage execution evidence are an unstarted direct-import state, not historical execution.

The manifest binding is excluded machine authority and neutralized to NULL in portable projections. Root relationship, policy, plan, limits, consumption, time and state are historical nonreplayable fields; no credentials, endpoint or text is stored. Exported budget rows and related root runs are frozen. Restoring a verified pre-M17 package can create new NULL legacy markers which were necessarily absent from its sidecar: accept only that strictly non-executable shape under the validated old source schema and corresponding frozen source runs. A schema18 package missing required budget history/freeze is rejected. New local lineages in a mixed restored project remain independently admissible; no copied budget or grant becomes execution authority.

The six chapter-binding fields are separately classified as nonreplayable history, including validated or consistently remapped semantic IDs. Export freezes the binding and its owning run, not every later local run which reads the same historical snapshot. A verified pre-M17 restore may acquire only the migration's own-row historical bindings; the narrow exception cannot authorize new execution or alter old content. For frozen non-parsing lineages with a non-legacy budget, require every run's provably expected binding count and associated snapshot sizes to equal the preserved input metadata, in addition to foreign keys and two-way freeze coverage. Legacy partial histories remain distinguishable and are not invented as complete. Portable projection excludes the original authorization fingerprint: these checks do not recreate it or provide source-signature authentication against a party rewriting all archive metadata.

## Visible State And Qualification

No new layout, control, stage, resource or copy. Budget refusal uses the existing localized import integrity/check-failed area with its exact diagnostic code, as in ADR-0070. Do not reuse text promising that an in-flight request was aborted or that Continue import replenishes a budget. The new failed state follows F2's required budget dispatch/effect refusal, legacy uncertainty and unknown recovery. It does not alter author content or imply visual acceptance.

Required evidence includes actual foreground controller/KB integration, same-root restart and reauthorization, parameter changes without added credit, atomic last-request competition, parallel activity union and gaps, time exhaustion at both effect boundaries, clock/settlement failures, closed/open restart, legacy migration rollback and both schema generations of portable recovery. This bounded decision does not complete SCHED-001/002, import migration, production headless, literary quality or platform qualification.
