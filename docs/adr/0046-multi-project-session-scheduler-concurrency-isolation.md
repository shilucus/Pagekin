# ADR-0046: 多项目会话并发隔离与调度队列边界 (SCHED-002)

- **状态**: Accepted
- **日期**: 2026-11-08
- **参与者**: 架构组、主进程运行时组、独立审查组
- **关联功能**: `SCHED-002`, `DRIVER-001`, `DRIVER-002`, `RUNTIME-003`
- **关联证据**: E09, E11, E23, E25, E27, I01, I08, ADR-0021, ADR-0023, ADR-0036

---

## 背景与问题陈述

在桌面多作品创作环境下，用户可能同时打开或切换不同小说项目。如果主进程模型调度器采用全局扁平队列，会导致如下系统级隐患：
1. **跨书阻塞**：一本作品进行大篇幅背景章节生成或遇到模型接口限流排队时，全局队列被占满，导致另一本正在交互写作的作品被无故阻塞；
2. **跨书串扰与脏写**：当用户切换项目或重签租约（Lease）时，旧项目排队中尚未启动的生成请求若仍然被放行，其生成产物或事件会误写入当前活跃项目；
3. **取消与泄漏风险**：任务取消、窗口关闭或网络异常时，如果本地并发预算没有立即回收，或者因请求失败盲目重试，会导致凭据被长期占满甚至并发配额耗尽。

因此，`SCHED-002` 明确要求：**按项目会话隔离并发与队列，跨书/切换/取消不串扰；保留主进程刹车与取消，不引入常驻调度器/多进程竞争/隐式重试**。

---

## 决策核心

### 1. 会话绑定与切换拦截 (AC-1)
- 生成调度准入严格基于项目会话标识 `projectKey`（由 `projectId` + `leaseId` 或规范路径派生）；
- 会话生命周期与物理项目根绑定：
  - 当项目关闭、会话切换或租约变更时，旧会话未启动的请求在调度器准入或出队执行点被立即拦截并抛出会话失效拒绝；
  - 严禁已失效旧会话的请求向外部模型提供商发包，确保旧会话产物与事件零跨书串扰。

### 2. 多项目独立并发与排队预算 (AC-2)
- 主进程调度器（`MainProcessScheduler`）通过内部 `projectCounts: Map<string, number>` 独立追踪每个项目的活跃并发数；
- 策略配置严格限定：
  - `policy.project`: 单项目最大并发数（如 1 或 2）；
  - `policy.global`: 主进程总并发上限；
- **一书超限不阻塞他书**：
  - 当项目 A 的活跃并发数达到单项目预算（或其排队已满）时，新进入的请求在项目 A 的队列中等待；
  - 此时项目 B 发起的生成请求，由于属于不同的 `projectKey`，直接分配属于项目 B 的独立许可（Permit）派发执行，绝不被项目 A 的满载或超时挂起。

### 3. 取消出列与有界隔离回收 (AC-3)
- 传入的 `AbortSignal` 在排队阶段触发 abort 时，请求立即从调度队列中出列，抛出 `SCHEDULER_CANCELLED`，本地排队计数与预算立即释放；
- 区分三类终态：
  1. **任务取消**：释放本地配额，不无限向后补槽；
  2. **本地传输错误**：显式调用 `permit.finish()` 回收配额，报告精确错误；
  3. **远端未知/不可恢复故障**：调用 `permit.quarantine()` 将故障凭据放入有界隔离区（`maxQuarantined`），防止同一故障通道无限重发冲击远端服务；
- 退出或关闭项目时调用 `scheduler.close()`，所有尚未启动的排队任务全部拒绝，零遗留资源泄漏。

## 影响与验证

- **架构一致性**：与 ADR-0023（无本地 tokenliability 拒发，保留物理刹车）及 ADR-0036（项目租约隔离）完全一致；
- **验证方案**：
  - 编写专用集成测试 `electron/services/__tests__/multi-project-session-scheduler.test.ts`，验证多项目独立预算、一书阻塞他书畅通、取消出列释放配额以及换租约拦截。
