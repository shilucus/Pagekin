# 单书规划反馈多轮候选、结构化差异对比与原子采用设计

日期：2026-11-08。状态：已接受。
依据：[F2](../plans/2026-11-07-creation-runtime-modernization/README.md) 第 6.1、6.2、6.3 节、FEEDBACK-002 特性定义，以及现行 [ADR-0026](0026-planning-feedback-candidates-and-adoption.md)、[ADR-0027](0027-planning-feedback-outline-ranges.md)、[ADR-0028](0028-desktop-planning-feedback-ipc.md)。

## 1. 目标与范围

本设计落实 FEEDBACK-002：
- 在单书规划（大纲/世界观/核心设定字段）阶段，提供基于作者反馈意见（feedback）的多轮候选生成、结构化差异（diff）确认与原子采用流程。
- 不影响正文审修闭环，不影响原有单次直接生成与全量重写。
- 纯单书前台界面与主进程契约推进，不依赖多书调度器与多书运行时。

## 2. 交互流程与安全不变量

```text
选定目标字段/底稿 -> 捕获底稿 (capture) -> 输入反馈与约束 (feedback/constraints)
 -> 生成独立候选 (begin & execute & stage) -> 结构化差异对比 (diffProse)
 -> 多轮迭代 (C1 -> C2) -> 明确确认原子采用 (adopt) 或 放弃关闭
```

1. **未确认不写库**：候选生成与暂存全过程处于隔离状态，主数据库正式字段不发生任何变更；只有作者在差异对比界面显式点击“采用”时，才调用 `client.adopt` 发起原子持久化。
2. **保护当前未保存编辑**：发起修订前检查目标字段是否存在未保存缓冲；若存在未保存编辑，提示作者提交保存或保留当前未保存版本作为底稿，绝不无声覆盖。
3. **结构化差异对比**：复用 `diffProse` 逐字比较当前正式底稿（`baseText`）与所选候选（`candidateText`），清晰呈现新增与删除，并统计变动处数。
4. **多轮候选追溯（F0 -> C1 -> C2）**：支持在上一轮候选（C1）基础上追加反馈意见产生下一轮候选（C2）；C2 的生成父本为 C1，但采用基线依然指向正式底稿 F0；候选历史完整可追溯。
5. **CAS 与原子采用**：采用时由主进程在事务内校验 `baseId` 与当前项目来源版本，执行单字段写入与收据归档；若底稿在期间被作者在其他地方修改，采用被安全拒绝，不产生脏数据。
6. **失败与取消安全**：生成中途取消或网络超时不落库任何正式数据，已生成的不完整内容丢弃或仅保留为失败记录，不产生脏状态。

## 3. 采用回包与编辑器基线澄清

2026-11-11，[Stage49](../plans/2026-11-07-creation-runtime-modernization/stage-49-evidence.md) 修复既有采用链路，不改变界面或正式 writer：

- 主进程采用成功后，设定页仅发布该字段已提交的 saved baseline，不能再把 C1 当成基于 F0 的未保存编辑，也不再次写库。保留其他字段的未保存内容。
- 回调携带原冻结项目会话和采用点击时的字段值。回包时若该字段已有更新编辑，保留当前编辑并只推进其保存基线；否则显示采用值。迟到回包不能跨书或新 lease 发布。
- 采用回调只在原弹窗实例仍有效时发布；关闭时立即使原实例失效，防止旧 ACK 回退后来保存的基线或操作新弹窗。这不撤销主进程已提交的采用及收据；关闭后已提交结果的同步/恢复仍是独立未完成边界，不能称为取消或回滚。
- 同一打开的弹窗内，相同会话、目标、底稿、候选、决定和实际文本绑定同一个幂等键。失败回包不清除绑定；作者再次明确点击时可读取原操作收据，不自动重发。改变候选或实际载荷使用新键。关闭后重新打开的恢复与键持久化不在此增量内。

本澄清不代表“发起修订前处理未保存缓冲”、完整历史发现或下游影响展示已经实现；这些仍按各自验收和设计证据核定。浏览器模拟只证明页面/client/bridge 行为，真实收据与 CAS 另由原生持久化回归证明。

## 4. 设定字段重入时的正式值投影

2026-11-14，[Stage70](../plans/2026-11-07-creation-runtime-modernization/stage-70-evidence.md) 限定修复设定页六个字段：`coreOutline`、`writingStyle`、`protagonistProfile`、`worldSetting`、`goldenFinger`、`globalGuidance`。

- 重新打开意见修订时，沿用原 capture 请求取得主进程当刻的正式字段值；在请求发出前冻结当前完整项目会话及本地发布令牌。有效实例和请求仍属于该会话与目标时，才可通知设定页发布该字段。不复用采用回调，不显示采用成功提示，不新增保存、采用、重发或自动重新捕获。
- 干净字段显示该正式值；同字段或其他字段的未保存编辑保留，使用既有 `unsaved-edits` 合并语义只推进目标字段保存基线。放弃草稿回到已知正式值，其他字段的正式基线和内容不变。
- 本地令牌不是主进程授权或持久化版本。后续配置保存、生成正式提交的发起或排空、其他正式值发布及放弃草稿使旧令牌失效；配置 writer 在途时不取得可发布令牌。值相同的新保存也属于新的写入时序。令牌失效时不改值、不推进保存基线，保留既有冲突与关闭行为。
- 关闭立即使实例失效；迟到的旧 capture 或采用 ACK 不得发布到新实例、另一部作品或同路径新 lease。此处只同步 capture 当刻已存在的事实，不能保证发现 capture 之后才提交的请求，不恢复关闭实例的幂等键或完整候选历史，也不改变两个架构目标的发布规则。

上述是既有正式事实的受保护界面投影，不增加可见操作、文案或布局，不替代未保存缓冲发起决策和完整反馈界面的设计证据门禁。
